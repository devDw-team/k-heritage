# K-Tour 여행코스 화면 개발 계획

## 📋 개발 목표
한국관광공사 Tour API의 여행코스(`contentTypeId=25`) 데이터를 활용한 여행코스 탐색 및 관리 화면 개발

## 🔍 현황 분석
- **기존 구현**: K-Tour 메인, 여행지 탐색, 상세 화면 구현 완료
- **API 연동**: TourAPIDataSource에서 areaBasedList2, detailInfo2 등 지원
- **아키텍처**: Clean Architecture (domain/application/infrastructure/presentation)

## ⚠️ 주의사항

### API 관련
- Tour API의 여행코스(`contentTypeId=25`)는 detailInfo2에서 특별한 구조 사용
- 코스 단계별 정보는 subcontentid로 연결
- 응답 필드: `subcontentid`, `subname`, `subdetailimg`, `subdetailoverview`, `subnum` 등
- **중요**: 코스 데이터는 일반 관광지와 다른 파싱 로직 필요
- API 호출 시 contentTypeId 파라미터 필수

### 성능 관련
- 지도 표시 시 경로 최적화 필요 (Polyline 사용)
- 이미지 lazy loading 적용 (cached_network_image 패키지)
- 대량 데이터 처리 시 페이지네이션 활용 (20개씩 로드)
- 코스 경로 계산은 백그라운드 처리
- 메모리 관리를 위한 이미지 캐시 제한 설정

### 데이터 관리
- 로컬 저장소는 SharedPreferences + Hive 병행 사용
- 오프라인 모드 고려 (최근 조회 코스 10개 자동 캐싱)
- 캐싱 전략: 24시간 유효, LRU 방식
- 나만의 코스는 별도 로컬 DB 저장

### 에러 처리
- 네트워크 오류 시 캐시된 데이터 우선 표시
- API 응답 없을 시 기본 추천 코스 표시
- 위치 정보 없을 시 전국 단위 코스 표시
